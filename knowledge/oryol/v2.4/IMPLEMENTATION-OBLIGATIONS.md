# Oryol Architecture v2.4 — Implementation Obligations (No New Semantics)

**Status**: PROPOSED ARCHITECTURE BASELINE (v2.4) — Subject to Independent Architecture Review

These are implementation findings from the independent principal review (`docs/reviews/ASTRA-PRINCIPAL-REVIEW-2026-09-06.md`, Oryol Core frozen candidate `932957c9176b1b2082d0fa62401c101f1f394c17`) that do **not** require new architecture semantics. v2.4 records them as binding implementation obligations for Oryol Core (Phase 1 Slice 4+). They are intentionally **not over-designed** here.

| ID | Obligation | Governing architecture (already sufficient) |
|---|---|---|
| **P1-01** | Real (physical) deletions MUST produce the aggregate version increment, the immutable audit event, and the transactional outbox event **exactly once** — in the same atomic transaction as the row `DELETE`. No delete path may skip version/audit/outbox, and none may emit them twice on retry. | v2.3 `audit-and-events.md §6.4` (atomic security mutations) + `data-lifecycle.md` deletion pipeline + [ADR-006 §2.1 / §4](adr/ADR-006-event-version-semantics.md) (one-event-one-version, command-scoped idempotency). |
| **P1-02** | Sensitive session routes (list sessions, revoke another session, logout-all, credential/recovery changes, security-policy changes, ownership changes) MUST perform authoritative presenting-session validation against committed D1 state — never trust edge signature verification alone. | [ADR-004 §7](adr/ADR-004-session-policy-and-refresh-recovery.md) `SENSITIVE_OP_AUTHORITATIVE_VALIDATION` (9-point check) + v2.3 `session-security.md §7`. |
| **P1-06** | Security-policy partial updates (`organization_security_policies`, `organization_ip_allowlist_entries`) MUST use stale-write / optimistic-concurrency protection: a partial `PATCH` reads the current `version`, and the atomic batch's `UPDATE ... WHERE organization_id = ? AND version = :expected_version` must affect exactly 1 row, else `ERR_SECURITY_POLICY_STALE_WRITE`. | v2.3 `authorization-model.md §2` (`organization_security_policies.version`) + ADR-001 §4.3 (atomic batch + version invalidation) — the `version` column already exists; the obligation is to actually gate on it. |
| **P1-07** | Migration existing-row taxonomy and semantic verification MUST be strengthened: the migration verification suite asserts taxonomy invariants, service-account ownership, authorization-subject relationships, deny grammar/resource shape, invitation tenant relationships, and required-row preservation over **existing** rows — not just object names. | [ADR-005 §5.2](adr/ADR-005-migration-verification-and-recovery.md) (semantic postconditions) + ADR-002 §7 preflight (re-asserted in-batch and post-commit). |
| **P1-09** | Hard-coded `aggregate_version` in emission code is **prohibited**. Every emitted event's version is allocated by the CAS bump of `aggregate_event_sequences` inside the mutation transaction. | [ADR-006 §2.1](adr/ADR-006-event-version-semantics.md) `EVENT_VERSION_ALLOCATION`. |

**Verification**: Each obligation is covered by an Oryol Core review-gate check and/or migration postcondition when Slice 4+ implements it. This document does not create schema; it pins responsibility.
